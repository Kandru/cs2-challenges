## Panorama versions

Repo keeps versioned sources `tracker_vN.xml`, `menu_vN.xml`, `hud_vN.vcss`. `PanoramaVersion` in [`Version.cs`](../src/Challenges/Version.cs) selects those at runtime. Bump only when panel ids / dialog vars / classes / structure would break old DLLs; keep older generations in the published addon.

## Theme / type / bars

**v5 "tactical" design** (see the header of `hud_v5.vcss`): square panels `#0a0d11eb` with 1px hairline and accent corner brackets (`TxCorner`, one top+left "L" turned with `rotateZ` - `border-right` is not in the known-good sheet), `//` kickers, `01` index boxes (`TxIdx`), segmented bars (clip-ladder fill under ten `TxSegCut` cells), checkbox task marks (open = empty box, done = filled success box, broken = red box on a tinted line). Menu = main panel (filter rail `TxNav` with label + count, 2×2 card grid) + scoreboard panel (chips `TxChip`, rank card, medal colours via `rank-1/2/3`). Gold `#f0a531` is the baked-in accent (`gui.theme`; `theme-*` via `HudTheme.Apply`, rules from [`tools/hud_themes.py`](../tools/hud_themes.py)). Text tokens: ink `#f5f7fa`, ink-soft `#e8eef4`, muted `#a3acb6`. Type scale: tracker **14 / 16 / 18 / 22** at 100%, menu **16 / 18 / 20 / 24 / 32** (floor 16; shared classes get their menu size under `.MenuRoot`). **Accent only** for brackets, kickers, index boxes, values, active state and own entries; semantic colours never follow the theme. Horizontal insets are `TxPad` spacers (width:100% children ignore padding). Menu fades 0.25s in / 0.18s out; tracker keeps 1.0s. Bars: `p0`…`p100` (`SetStepPercent` 10% challenge fills; `SetPercent` 1% = timer start position; `p0` = 0%). Tracker timer is drained by the client: start p-class, next tick `span-N` + `is-running` (`Tracker.StartTimer`), no writes while it runs.

## Text

Labels use `text="{s:…}"` except literal `Label.MenuCredit`. Server fills from `lang/en.json` / `lang/de.json` via `Context.Text`. Blueprint titles: `Titles.For` (culture → two-letter → first). Formats: `hud.format.page|percent|count|rank`, `hud.menu.when.*`. Completer self-slot: `hud.menu.you` + `is-you`.

## Terms

**Blueprint** = YAML definition. **Challenge** = winnable instance (all visible tasks done). **Task** = step; `visible: false` stays off both HUDs. Modules inherit `Module`.

## Server can only

1. Dialog var on the layout root card → Label text (never path/colour).
2. `SetHasClass` on a panel **id**.

No panel create / width / colour / image from C#. Layout edits need VPK republish.

**Authored state:** [`HudAuthored.g.cs`](../src/Challenges/Hud/HudAuthored.g.cs) (generated by `make panorama` from the current layouts) lists the classes of every id'd panel. On a slot that was never written since our entity spawned (`_pristine`), a class cache miss falls back to it, so the first paint sends only deviations from the XML. Never edit the `.g.cs`; change the XML and rerun `make panorama`.

**Open:** chat command → `HudMenu.RequestOpen` (0.2s timer, token-cancelled by a second command, close or release) → `Menu.Open`. Layouts are spawned by `CustomHud.WarmUp` 1s after map start. Timers are cancelled by token, never `Kill()`ed.

**Round restart:** layouts survive rounds; client resets XML defaults while server keeps last classes/vars. `HudDriver.EventRoundStart` → `CustomHud.ResetRound()` → `Tracker`/`Menu`.`WriteDefaults` + drop ledger. **XML defaults must match `WriteDefaults`.** Never Kill/respawn live layouts; `Shutdown` only on map end/unload.

**Fade:** show = `ph-fading` then clear next frame; hide = `ph-fading` 1s then `ph-off` (not in the same write). The tracker timer bar stays through the fade-out (its drain just runs out); the next show restarts or hides it. **Tick:** 2 slots/tick; `Tracker.Refresh` paints only in freeze or progress hold.

### Tracker ([`Tracker.cs`](../src/Challenges/Hud/Tracker.cs))

Top-right 420px by default, never clickable. Player settings (`HudSettings`, saved in the player file `hud` block, defaults `gui.tracker_position` / `gui.tracker_size`) put class groups on the root: `pos-r` / `pos-tl` / `pos-l` and `size-80/90/110/120` (top-right and 100% = no class). Size rules scale every tracker metric and are generated from [`tools/hud_scales.py`](../tools/hud_scales.py) (`make panorama`; no `transform-origin` in the known-good sheet). `WriteDefaults` clears both groups, `Paint` applies them. Widget off = `ShowFreeze` / `ShowProgress` / `ShowRuleBroken` return early and `Paint` hides. **Preview:** `TrackerPreview` holds the overview like freeze while the settings view is open (dropped when the menu is gone). Title + count in the head, hint (`!c`) in the footer, rows numbered `tr_n*` (01…); up to 5 rows (`gui.tracker_rows` default 3). **Freeze** (`mp_freezetime > 0`): unsolved, % desc, unsolved tasks only, drain = freezetime. **Progress:** `ShowProgress` kinds Progress/TaskSolved/ChallengeSolved; challenge solved → up-next after `gui.progress_duration`. **Rule broken:** queue via `ShowRuleBroken`; freeze clears queue; after freeze, remaining breaks play. **Intermission:** `cs_intermission` → `Tracker.Hide` (map vote).

### Menu ([`Menu.cs`](../src/Challenges/Hud/Menu.cs))

`!c` → mouse capture. Head shows `menu_count` (solved / schedule of the viewed player). Filter rail all/solved/progress/ending/starting, label `menu_f_*` + count `menu_fc_*`; paginated 2×2 grid (4 cards/page, unused slots keep their place via `empty` = opacity 0, no scroll); cards `ch-mrow-0…3` are non-clickable, numbered `m*_n` across pages; scoreboard inspect sets `MenuSubjectSteamId` (list shows that player’s progress); ending/starting windows 7d. Tracker `z-index` 99998 under open menu.

### Settings view ([`SettingsMenu.cs`](../src/Challenges/Hud/SettingsMenu.cs))

Head button `ch-settings` → `view-settings` on the `Menu` root collapses `MenuColumns` and shows the centred panel `ch-set` (so the tracker preview stays visible at the edges). `ch-set-back` returns, `ch-set-close` closes. Switch `ch-set-show` (`is-on`; `tracker-off` on `ch-set` dims position and size), position picker `ch-set-pos-tl/tr/l/r` (`active`), stepper `ch-set-size-dec/inc` (`is-disabled` at the ends). Vars `set_*`, `menu_settings`. XML defaults = widget on, top-right, both steps enabled; `SettingsMenu.WriteDefaults` writes the same. `Menu.Paint` paints only the settings while the view is open.
